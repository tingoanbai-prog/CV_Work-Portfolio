# NBA Fantasy

以 PHP + MariaDB（MySQL 相容）實作的 NBA 球員選秀對戰遊戲：玩家在預算內從匿名球員表選出 5 人，與電腦組成的陣容對戰，依結果累積積分並登上排行榜。

2024年資料庫管理課程作業（多人合作），並於2026 年以Claude協作檢視與修正。原專案中我負責球員資料庫的建立與調整、遊戲內容發想；2026 年的重構（資料庫、規則、安全性、程式結構）則由我獨立完成。

## 重構重點

原版是「頁面、規則、資料庫存取混在同一個檔案」的課程作業，球員表沒有主鍵、字串拼接 SQL、對戰紀錄只有彙總。重構集中在資料庫與 SQL：

- **資料庫設計**：player 表加入主鍵並重建為 182 筆資料；新增 `matches` 對戰明細表（外鍵、ENUM、`ON DELETE CASCADE`），`users` 為彙總、`matches` 為明細，可互相核對。
- **交易寫入**：每場結果以 transaction 同時寫入 `matches` 與 `users`，任一步失敗整筆還原，重新整理頁面不會重複計分。
- **SQL 安全性**：所有含使用者輸入的查詢都改用 prepared statement；無法用 `?` 綁定的欄位名稱只接受伺服器端白名單；選人只傳本局列號，由伺服器換回真實 id 並驗證。
- **資料管線**：以 Python 串接第三方 API，經清洗去重後自動產生 SQL 匯入檔。
- **規則與設定分離**：規則數字集中在 `includes/game_config.php`，規則函式在 `includes/game_logic.php`，除讀資料庫的函式外都可不靠資料庫單獨測試。

## 遊戲規則開發說明

| 項目 | VIP | 一般玩家 |
| --- | --- | --- |
| 預算 | $18 | $15 |
| 每局顯示能力項數（20 項中隨機抽） | 12 | 10 |
| 球員池 | 現役＋傳奇 | 僅現役 |
| 選人數 | 5 人，不限位置 | 5 人，不限位置 |

- **電腦難度**：簡單、困難、名人堂的預算分別為 $12、$15、$17；電腦每個位置各選一人、總價剛好用滿預算。
- **球員狀態**：依價格決定機率，總評 ±0.5。$5：火熱 40%／正常 50%／冰冷 10%；$2–4：25%／60%／15%；$1：20%／60%／20%。
- **陣容加減分**：PG＋SG 共 2 人、SF＋PF 共 2 人、C 共 1 人時 +3；PG＋SG 為 0 人，或 SF＋PF 為 0 人時 −3。
- **勝負**：比較「總評＋陣容＋狀態」的總分，較高者勝，相同為平手；結果畫面不公布總評。
- **積分**：簡單 勝 +1／和 0／敗 −3；困難 +2／0／−2；名人堂 +3／+1／−1，積分可為負。
- **排行榜**：依積分 → 勝場 → 場數少 → id 排序；勝率 = 勝場 ÷ 總場數。提供玩家間進行比較。

## 技術

PHP（mysqli）、MariaDB（XAMPP 內建）、HTML／CSS／JavaScript、Python 3（`requests`，僅資料處理工具使用）。

## 資料庫建置

| 資料表 | 說明 |
| --- | --- |
| `player` | 182 筆球員（現役 133＋傳奇 49）；`id` 為主鍵，`(Position, VIP)` 建立索引；含 20 項能力欄位與 `Price` |
| `users` | 帳號、VIP、彙總戰績（GP／W／D／L／WinPercent／Points） |
| `matches` | 每場對戰明細：玩家、難度、結果、積分、雙方比分與總分、雙方陣容的 player.id；`user_id` 外鍵，`ON DELETE CASCADE` |

排行榜查詢：

```sql
SELECT username, Points, GP, W, D, L, WinPercent
FROM users
ORDER BY Points DESC, W DESC, GP ASC, id ASC;
```

勝率與戰績更新放在 transaction 內，`WinPercent` 排在 `SET` 最前面並直接使用「加 1 之後」的值，不依賴資料庫套用 `SET` 的順序：

```sql
UPDATE users
SET WinPercent = (W + ?) / (GP + 1),
    GP = GP + 1, W = W + ?, D = D + ?, L = L + ?, Points = Points + ?
WHERE id = ?
```

## 資料處理工具

球員資料由 `tools/` 的三支腳本產生，流程為「抓取 → 清洗 → 產生 SQL」：

```
python tools/nba2k_simple.py         # 呼叫 NBA 2K API，輸出 raw_data/ 下的 JSON
python tools/nba2k_datacleaning.py   # 去重、移除不需要的欄位、同球員多賽季版本取總評最高者
python tools/build_player_sql.py     # 產生 sql/nba_fantasy.sql；任一筆資料有問題就停止，不產出半套檔案
```

原版課程作業的待修清單與目前狀態：

| 問題 | 狀態 |
| --- | --- |
| 字串拼接 SQL（SQL Injection） | 已解決：所有含使用者輸入的查詢改用 prepared statement，無法綁定的欄位名稱以白名單限制；含單引號的 email（如 `o'neil@example.com`）可正常註冊與登入 |
| 安全性問題：<br>1. HTML 輸出未跳脫（XSS）<br>2. 未登入可直接開啟遊戲頁<br>3. 換帳號沿用前一位使用者的局 | 已解決：<br>1. 輸出經 htmlspecialchars 跳脫；選人表單不再放球員姓名，姓名含撇號的球員（如 De'Aaron Fox）也能正常選取<br>2. index.php 開頭檢查登入，未登入導回 login.php 並立即停止執行<br>3. 登入成功時清除舊的本局資料，換帳號後一定重新選難度 |

| 遊戲規則問題：<br>1. 平手判定順序錯誤<br>2. 勝率公式不一致<br>3. 超出預算的球員仍會上場<br>4. VIP 宣傳預算 18、程式固定 15。<br>5. 重新整理重複累加戰績 | 已解決：<br>1. 總分相同才平手，不再有「差 3 分內」的區間。<br>2. 統一為勝場 ÷ 總場數<br>3. 伺服器端驗證總價不超過預算<br>4. VIP $18／一般 $15，由設定檔決定<br>5. 結果存入 session 後不再重算，並以 transaction 寫入 |

## 新增功能

- 匿名選人 board：不顯示姓名、球隊、位置、總評，只顯示價格與本局隨機抽中的能力值；球員順序每局打亂
- 三種電腦難度：簡單、困難、名人堂
- 球員狀態（火熱／正常／冰冷）、陣容加減分
- 對戰結果視窗（四節計分板與得分事件播放）
- 規則說明視窗
- VIP 退出功能，並讓 VIP 預算 $18 實際生效（原版宣傳 $18、程式固定 $15）；VIP 可選傳奇球員，一般玩家僅現役
- 排行榜由勝率排序改為積分制，積分依難度與勝平敗計算

## 已知限制

- **資料庫帳密寫在程式內**：`database.php` 以 root、無密碼連線，為 XAMPP 本機開發的預設設定，不適合直接部署。
  - 影響：root 可存取伺服器上所有資料庫，若未來出現注入漏洞，損害不會只限於本專案；帳密寫死在程式中，換環境就要改程式，也會隨程式碼公開。
  - 改善方向：建立只有 `nba_fantasy` 權限的專用帳號，只授權程式實際用到的 SELECT、INSERT、UPDATE（最小權限原則）；帳密移到不提交到 Git 的設定檔，另附 `config.example.php` 範本。全專案只剩 `database.php` 一個連線檔，只需修改一處。
- **表單沒有 CSRF 防護**：加入／退出 VIP、開新局、開始比賽等表單，伺服器只確認使用者已登入，沒有驗證請求是否來自本站頁面。
  - 影響：其他網站可誘使已登入的玩家在不知情下送出請求，例如切換 VIP，或代打一場比賽而影響積分。更改密碼需要輸入舊密碼，不受此影響。
  - 改善方向：在 session 產生隨機 token，放進每個表單的隱藏欄位，伺服器收到後用 `hash_equals()` 比對，不符就拒絕。
- **登入沒有嘗試次數限制**：`login.php` 可無限次嘗試密碼。
  - 影響：密碼雖以 `password_hash()` 雜湊儲存，但線上暴力猜測仍無法阻擋，弱密碼帳號風險較高。
  - 改善方向：依帳號或 IP 記錄失敗次數，連續失敗後暫時鎖定或逐次拉長等待時間。
- **密碼沒有強度規則**：註冊與更改密碼只檢查「不是空白」和「兩次輸入一致」，沒有最低長度。
  - 影響：使用者可以設定 1 個字元的密碼，搭配上一項更容易被猜中。
  - 改善方向：伺服器端驗證最低長度（例如 8 字元），前端的 `minlength` 只是輔助提示，不能取代伺服器檢查。
- **測試程式未收錄於專案**：開發期間曾以單元測試與 Playwright 瀏覽器測試驗證規則與介面，但測試腳本沒有放進專案，其他人無法重新執行。
  - 改善方向：把 `game_logic.php` 的單元測試放進 `tests/`；規則函式除讀資料庫者外都只接收與回傳陣列，不需要資料庫就能執行。
- **尚未實作的功能**
  - 註冊信箱驗證：目前可用任何 email 註冊，包括不屬於自己的信箱。
  - 忘記密碼：需要寄送重設連結的郵件服務，原版的死連結已移除。
  - VIP 沒有付款流程：按一下即可加入，目前只是遊戲內的等級切換。
